# 系统设计

## 数据流

```text
Chrome 麦克风 / 文字输入
  → 本机桌面服务
  → 灵矽 ASR / Agent
  → 游戏 MCP
  → 输入解析 / 标准问法 / 两阶段语义裁判
  → SQLite 状态与计分
  → 灵矽 PCM TTS
  → Web Audio 播放与桌面角色
```

麦克风音频使用 AudioWorklet 编码为 16kHz、单声道、20ms 的 PCM 帧，每帧 640 字节。设备 token 由本机服务通过 HTTPS OTA 获取，随后使用 WSS 连接平台，不进入浏览器。

文字与按钮通过平台 `listen.detect` 进入相同流程，不经过浏览器 Speech API。独立文字版页面的浏览器语音辅助属于另一条入口，不占用绑定设备。

## 服务边界

- `src/server.js`：游戏 HTTP API、认证和 Streamable HTTP MCP。
- `src/pet-server.js`：只监听本机的设备与音频桥。
- `src/engine.js`：玩家锁、状态、裁判请求、提交与计分。
- `src/device-view.js`：认证设备/会话映射及短期输入登记。
- `src/library.js`：命令、标准问法与提示选择。
- `src/replay.js`：真实事件记录与公开回放。
- `public/pet/`：角色、对话、录音和播放交互。

游戏状态按设备、Agent 和业务会话隔离。MCP 使用无状态 HTTP transport，但业务会话和游戏状态仍存在。桌面界面换题会建立新的平台语音会话；上一局只读回放保留在当前页面内存，不写回新会话。

## 可信输入

桌面服务先登记按钮/文字原文；语音在收到平台 STT 后登记识别原文。登记绑定设备、会话和随机输入凭据。

存在有效登记时，MCP 使用登记原话并从默认 `say` 解析动作，不采信模型改写的 `text/action/caseId/confirm`。模型不能通过参数把问题改成提示、替玩家确认揭晓，或构造更完整的答案。

同一输入凭据的工具重试复用结果；新的输入会使旧的异步判断失效。输入登记与去重是单实例短期内存机制，语音登记仍依赖 STT 事件时序；没有登记的客户端继续使用普通 MCP 入参，不享有这层绑定保证。

## 两阶段裁判

1. `mystery_turn` 解析原话。开局、提示、复述和确认等操作直接产生结果。
2. 标准问法精确核对；自由问题和完整作答返回 `requiresJudgment=true`、空 `answer` 及内部 `privateContext`。
3. Agent 按当前事实与因果规准调用 `mystery_commit`。
4. 服务端验证 requestId、玩家、游戏、版本、有效期、证据与逐字引文，推进状态并返回 `answer`。
5. Agent 播报结果；分数、通关和揭晓不能由模型直接写入。

裁判请求有效期为 5 分钟。重复提交返回原结果；题目变化、提示或其他版本变化使旧请求失效。格式、证据或引文不合法时不扣次数。

`privateContext` 仅用于平台模型内部判断，不发送给桌面页面。它不是对模型保密的隔离区：模型可以接触真相，格式校验也不能证明语义一定正确。

## 交互与恢复

- 语音连接成功后，收到游戏开局记录才开放麦克风。
- 文字、提示与重听不与当前播报抢发；录音和方块按钮保留显式打断能力。
- 新播报从 `tts.start` 开始，孤立句尾和打断后的残帧不拼入下一轮。
- 检测到明显工具调用代码或内部字段文本时停止输出。
- 开局未确认时最多以同一输入凭据重发一次，不自动重试问答或答案提交。
- 长等待先提示；若已有服务端结果，语音超时后可展示该结果的文字备用，不重新执行操作。

## 安全与数据

- 本机终端校验 Host、Origin，使用 HttpOnly、SameSite Cookie，单设备单活。
- 公网平台接口需要 Bearer 令牌；玩家身份取自可信平台请求头，不取模型参数。
- 前端通过 `textContent` 渲染文本；响应带 CSP、跨站限制和请求大小限制。
- 未揭晓的当前题不下发真相、评分规准或完整事实库。
- 设备 token 只驻留服务端内存；输入、进度和文字可存入 SQLite，不保存录音。
- 回放只公开已经发生的记录，破案卡在浏览器本地生成。

服务令牌持有者可以伪造身份头，因此令牌只应交给可信平台。题库源码公开，不防止通过源码查答案。日志和诊断不能替代语义评测或独立安全审计。
