# 小矽：桌宠式虚拟硬件与真正可玩的推理游戏

## 现在怎么玩

在项目目录运行：

```bash
pnpm install --frozen-lockfile
pnpm pet
```

会检查并复用已有游戏服务；没有启动时尝试启动本机游戏引擎，然后开启桌宠服务和独立 Chrome 小窗。不会关闭或接管已有游戏引擎进程。

本机入口：**http://127.0.0.1:3212/**

- 点 **唤醒并开始**：真实连接灵矽，自动讲第一题，不需要先操作终端录音。
- 点 **点击说话**：浏览器请求麦克风权限。说完再点一次发送；不是常驻监听。
- **给个提示 / 重听故事 / 下一题**：按钮通过平台的 listen.detect 文字指令进入同一个 Agent 游戏流程。
- **展开推理台**：看题面、已确认的是/否问题、真实对话与分数；也能用文字继续玩。
- **我要作答**：输入完整解释，界面明确以答案方式提交；语音作答则先说“我的答案是”。
- **揭晓或中途换题**：先确认，不能悄悄代替玩家放弃。
- 点方块打断播报；点 **让小矽休眠** 断开连接并关闭音频。
- 拒绝麦克风权限时自动展开文字模式，不把玩家卡死在等待页面。

```bash
pnpm pet --no-open  # 只启动服务，不自动打开窗口
pnpm pet:open      # 对已启动的服务再次打开桌宠窗口
```

新机器没有设备绑定时，窗口展示真实 OTA 绑定码；在已有灵矽 Agent 中添加设备后重新唤醒。已绑定的本机身份沿用 `.local/lingxi-device.json`，无需重复创建。

## 它是什么，不是什么

这是**桌宠式语音终端 + 虚拟硬件演示**，有待机、倾听、思考、播报、破案和错误状态，以及真实音量驱动的音频指示。桌宠动作与“设备提示”明确标记，不冒充 Agent 生成的对话。

它目前使用独立 Chrome app 窗口，不是透明、穿透或系统级置顶的原生桌宠，也不是实体嵌入式硬件。新做的入口是本机 3212 端口；旧规则页面保留作备用，公网上的 `/pet/` 只提供外观预览和本机启动说明。

## 真实链路

```text
浏览器麦克风（点击后）
  → AudioWorklet：16kHz / 单声道 / 20ms PCM
  → 本机 WebSocket 桥（127.0.0.1:3212）
  → 灵矽 WSS：ASR → 现有 Agent → 游戏 MCP / 两阶段判断
  → 灵矽 PCM TTS
  → Web Audio 播放 + 桌宠播报状态
```

不是 Web Speech API、浏览器云端语音识别或假对话。文字/按钮输入不经过 ASR，但确实经过平台 Agent 和游戏 MCP，不是本地关键词回复。

为降低接入复杂度，这个桌宠入口不需要 Python、PortAudio 或 libopus；仍保留同仓库的 uv/Python 终端用于兼容与诊断。

## 真实验收

修复输入去重后，在两个新建会话中运行 `pnpm pet:check --allow-platform`，均完成：

1. 浏览器点击唤醒，真实 Agent 开局，题面从服务端同步到推理台。
2. 用预录音频替代物理麦克风，经浏览器 getUserMedia、AudioWorklet、本机桥和真实灵矽 ASR 得到“房主听力正常吗”，返回“不是”。
3. 文字询问蓝色衣服，返回“无法确定”，没有增加有效提问次数。
4. 一次提示操作。
5. 通过“我要作答”提交自然语言解释，真实语义判题通关，界面确认 **85 分**。
6. 切到《雨天的十八楼》。
7. 休眠、关闭音频连接。

检查时浏览器静音，没有录制或播放本机真人音频；PCM 返回已进入浏览器播放管线。**物理麦克风的现场识别率、扬声器主观听感、回声/噪声、长时间体验仍需要真人试玩。**

自动 UI 回归还覆盖完整窗口与桌宠小窗、录音开关、提示、文字模式、结算、换题、取消揭晓和麦克风权限拒绝后的文字回退，但这些 UI 回归使用模拟 Agent，不能冒充真实平台测试。

## 修复的一次真实问题

首轮真实测试发现：仅点一次提示，Agent 的重复工具调用消耗两级提示，结算成 70 分。

已为桌宠输入增加登记凭据：

- 文字/按钮先由本机桥登记唯一 inputId 和原话，再交给灵矽。
- 语音在收到平台 STT 后登记同一轮输入。
- 同一输入的重复 turn 复用原结果，不重复扣提示分；不同真实输入仍可正常获得下一提示。
- 新输入使旧的异步判断失效；工具传入文本不能改写已登记的原话。
- 合并平台对按钮文字的 STT 回显，避免 UI 把同一句重复显示成两次玩家发言。
- 思考期间禁用重复操作，但保留打断和开始说话的能力。

修复后两个真实浏览器会话均确认一次提示、一次答案提交，得分 85。输入去重缓存和登记为单实例短期内存状态；重启、语音 STT 事件时序和跨端行为仍需进一步测试，不能称为通用的 exactly-once 分布式保证。

## 本机安全边界

- 桌宠服务强制监听 127.0.0.1；校验 Host 和 Origin，阻止 DNS 重绑定与跨站请求。
- 本机浏览器通过 HttpOnly / SameSite=Strict 短期 Cookie 连接语音，默认只允许一个桌宠窗口使用同一设备。
- 设备 token 通过 HTTPS OTA 获取，仅驻留本机服务端内存；不发给浏览器，不落盘、不打印。
- 游戏状态和输入登记接口仍需要服务令牌；令牌留在本机桥，不进入网页 JS。
- 游戏视图再次投影，未结束时不返回 truth、评分规准、pendingJudgment 或 privateContext；桥不转发任意 MCP/custom JSON。
- 录音约 45 秒上限，结束/休眠/窗口关闭时停止采集；没有自动常驻录音。
- **不要把 3212 端口加入 frp 或公网反代。** 它依赖本机信任边界，不是公开多租户语音网关。
- 不要同时运行 Python 语音终端和桌宠占用同一个虚拟设备，平台可能结束旧连接。
- 原有 Agent 防剧透与误判风险仍存在，见 agent-host.md；桌宠外观不能提升模型本身的语义正确率。

## 测试命令

```bash
pnpm test
pnpm test:e2e
pnpm voice:test
# 以下会使用真实平台资源，并可能产生语音/模型费用：
pnpm pet:check --allow-platform
```

真实界面验收脚本需要 macOS say、ffmpeg、Chrome 和 Playwright 开发依赖；**普通桌宠运行不依赖 say/ffmpeg**。脚本使用预录音频与静音浏览器，失败立即记录，不自动重试刷通过；报告、截图在忽略目录 `eval-results/`。

## 下一步优先级

1. 真人完整玩一局，修体验问题，特别是麦克风权限、等待、打断和“我该说什么”。
2. 减少等待、增强出错恢复与启动保活；不为做动画牺牲语音可用性。
3. 加 2–3 道原创精品题和围观时能理解的推理回放。
4. 原生透明置顶包装、更多动作和装饰均排在玩法与稳定性之后。

本次需求、实现与自查以“能打开、能操作、能完整玩”为验收，不以接口数量或动画数量代替可玩性。没有独立外部安全审计。
