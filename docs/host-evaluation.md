# AI 主持真实接口评测：未通过上线门槛

## 配置兼容修复

原配置提供了完整 `/v1/chat/completions` 地址，初版代码重复追加路径，导致 43 个请求均为 404。这是客户端路径拼接错误，不代表模型答错。

已兼容基础 `/v1` 地址与完整 `/v1/chat/completions` 地址，也支持末尾斜杠；新增回归测试。接口错误只记录错误类别和 HTTP 状态，不记录请求凭据或供应商响应正文。

## 修复后的两轮开发评测

同一 43 条人工标注开发集，运行时保留 8 秒请求期限，不在超时后重试伪装成一次成功。试验中未自动切换公网 AI 模式。

| 指标 | 供应商默认推理参数 | 显式 low 推理参数 |
|---|---:|---:|
| 总样本 | 43 | 43 |
| 有效返回 | 20 | 17 |
| 与标注一致 | 20 | 16 |
| 超时 | 23 | 26 |
| 端到端通过率 | 46.5% | 37.2% |
| 仅有效返回的标注一致率 | 100% | 94.1% |
| 标注安全样本端到端通过率 | 33.3% | 26.7% |

安全样本中很多失败是超时，不能称为“模型遭到注入攻击”；但真实体验中拒绝提供可靠结果仍然是失败，不能从总体通过率中删去。

P95 观察值约 8 秒，受到客户端截止期限截断，不能据此认为上游真实 P95 仅为 8 秒。low 参数没有证实改善，已撤销本地试验配置，保持供应商默认值。

第二轮有 1 个有效返回与标注不一致，为开放式未知细节问题的 unknown / clarify 边界。该分歧需人工审查，不将它直接等同于故事事实幻觉，也没有为过关而修改标注。

## 当前结论

- 模型配置已经可用，不再是“缺少凭据”的阻塞。
- 当前主要阻塞是响应时延与稳定性，不符合实时语音和竞赛展示要求。
- 尚不能从仅 20 个或 17 个有效返回推断整体语义质量，更不能认定通过独立盲测。
- 公网继续使用规则模式。AI 模式故障时会明确拒答且不扣次数，不用规则答案悄悄冒充模型成功。
- 少量替代模型/参数探测不构成候选模型排名；没有自动更换配置的模型，也没有宣称其他模型通过。

## 下一步

1. 选择提供低时延保障的轻量模型或更稳定的兼容接口。先用正向、否定、未知、注入、判题各一条做小规模冒烟，再完整跑集。
2. 完整开发集门槛仍为总体 ≥95%、安全样本 100%；单独记录运行时限内成功率和服务端判断 P95，目标 ≤4 秒。
3. 达标后扩充独立盲测和实际灵矽多轮语音验收，再切换 AI 模式。
4. 不通过增加超时时间、删除超时样本、缓存评测答案来制造通过结果。

完整运行报告保留在本机忽略目录 `eval-results/`，不包含 API key，不将带本地供应商配置的原始报告公开提交。
