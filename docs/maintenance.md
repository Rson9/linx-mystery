# 维护指南

## 日常检查

需要 Git 和已安装的 Google Chrome。测试使用独立端口 `3211/3213/3214/3215`，不要让其他服务占用这些端口。

```bash
pnpm check
```

该命令依次检查题库、Node 服务和浏览器交互，不访问真实灵矽。浏览器用例使用模拟 Agent，覆盖桌面/手机布局、录音开关、提示、确认、计分、回放、下载、权限回退、超时恢复、播报串行和开局就绪状态。

可单独运行：

```bash
pnpm library:check
pnpm test
pnpm test:e2e
pnpm voice:test
```

`voice:test` 使用 uv 管理的 Python 环境；原生编解码测试需要 libopus。缺失依赖而跳过的检查不能计作原生音频通过。

0.3.0 软件回归结果：85 项 Node 测试、15 项浏览器/原生窗口流程、21 项 Python 测试通过，无跳过项。记录环境为 macOS 与 Google Chrome；其他目标环境需核对依赖、音频设备和权限。

## 原生应用检查

```bash
pnpm desktop:build
pnpm desktop:check
```

打包检查使用全新临时配置和独立端口 `3320/3322`，核对 ASAR 中的运行时、Node/SQLite、依赖、题库和角色，以及退出时的服务清理；不连接平台，不创建设备身份。原生窗口回归额外检查透明像素、置顶、隔离、有限权限、窗口展开、导航阻止和模拟指针拖动。

```bash
pnpm desktop:check:live --allow-platform --packaged
```

此命令沿用现有绑定身份，使用预录假麦克风和静音输出，检查打包应用的真实 ASR、Agent、MCP、PCM TTS、自由问题、85 分语义作答、回放与 PNG 下载，并核对身份文件未变化。

预录检查实例通过 `--disable-features=AudioServiceSandbox` 允许音频进程读取测试 WAV。该开关只出现在显式联网检查中，正式桌宠启动不关闭音频沙箱；渲染进程仍保持沙箱与上下文隔离。检查会核对上行非静音 PCM，避免把未读到文件的零样本误当语音输入。

打包原生应用已完成上述固定联网流程，结算 85 分，收到真实 PCM，无页面异常，绑定身份保持不变。该结果不替代物理麦克风、扬声器和噪声环境评估。

## 真实平台验证

```bash
pnpm mcp:check
pnpm library:check:live --allow-platform
pnpm pet:check --allow-platform
```

- `mcp:check`：初始化与工具发现，不执行游戏。
- `library:check:live`：三道新题，覆盖语音输入、标准问法、自由问题、未知细节、错误因果、提示、判题、回放、破案卡、换题和休眠。
- `pet:check`：经典题的预录语音、一次提示、语义作答、85 分、下一题和休眠。

平台检查使用 macOS `say` 与 ffmpeg 生成预录输入，Chrome 使用假麦克风并静音。真实 ASR、Agent、MCP 和 PCM TTS 均参与；未采集真人麦克风，不以这些检查替代扬声器听感或噪声环境评估。工具请求失败会保留失败结果，不自动循环刷成功。

最近的联网验证中，新题完成 85 / 80 / 95 分，经典题完成 85 分；新题中的错误解释均先被拒绝再正确提交。该结果只覆盖固定流程，不是任意问法正确率、长期可用性或安全认证。

报告与截图保存于忽略目录 `eval-results/`。时延指标需要区分“发送至出现回复”和“发送至整段播报接收完毕”，不能混作首音延迟。

```bash
# 仅审计服务端执行与计分，记录平台播报；不认证语音内容正确性
pnpm library:check:live --allow-platform --controller-only
```

此诊断要求新服务端记录与当前原话对应，不能只凭口头“答对”判定成功。平台可能规范化引号、空格或改写输出，准确进度与结算以服务端记录为准。

## 健康与日志

```text
GET /healthz            游戏引擎健康
GET /api/catalog        公共题库
GET /healthz            桌面服务健康（PET_PORT）
```

启动日志输出到当前终端。需要保存时：

```bash
mkdir -p .local
pnpm pet --no-open > .local/pet.log 2>&1
```

原生应用会用 `.local/desktop-server.key` 验证复用的本机服务；文档、脚本、静态资源与 WebSocket 握手均校验随机挑战证明。旧服务不提供证明时应先停止并重启，不能仅凭健康标识继续加载。该密钥权限为 `0600`，不得提交或随应用分发；它不替代操作系统账户与文件权限隔离。

临时开启 `MCP_DIAGNOSTICS=1` 可输出安全的 MCP 事件。日志不包含服务令牌、玩家原文、设备/会话 ID 或工具参数。

| 现象或事件 | 含义与处理 |
| --- | --- |
| 请求没有抵达 `/mcp` | 检查公开域名、HTTPS、反向代理与平台出口 |
| 401 / `authValid=false` | 检查 Bearer 格式和服务令牌是否一致 |
| 503 | 服务未配置令牌或并发容量已满 |
| GET `/mcp` 返回 405 | 正常；MCP 使用 Streamable HTTP POST |
| 工具发现成功但没有实际 `tools/call` | 检查 Agent 工具挂载、实际工具名称和模型执行能力 |
| `input_envelope_normalized` | 按设备登记原话处理了模型参数偏差，不代表失败 |
| `turn_rejected` | 入参结构或游戏操作被拒绝；不会将拒绝视作完成 |
| `judgment_rejected` | 请求过期、证据、规准或逐字引文不合法；按反馈重新准备或提交 |
| 工具调用文本被当作播报 | 软件停止该段输出；检查实际工具执行，不要把代码文本当成游戏结果 |
| 本机显示语音已连接但没有开局 | 查看服务端是否创建了游戏；不使用预览题名代替开局确认 |

发现问题时优先记录：软件版本、发生阶段、服务端结果、界面状态和脱敏错误类别。不要在工单、聊天或公开仓库附带密钥、Cookie、设备身份或原始个人对话。

## 配置与模型

主路径复用灵矽 Agent，不需要额外独立模型密钥。模型应支持多轮工具调用，角色提示词见 [agent-host-prompt.txt](agent-host-prompt.txt)。工具能被查询到，不等于每轮都被实际执行。

模型思考参数与供应商接口应匹配。以 DeepSeek 为例，带工具的思考模式需要正确处理后续消息中的 `reasoning_content`；不要仅凭功能名称推断已正确接入，也不要在排障时同时修改多个参数。

可选独立模型适配通过以下命令单独评估：

```bash
pnpm eval:host
```

它需要配置 `LLM_BASE_URL`、`LLM_API_KEY` 和 `LLM_MODEL`，可能产生调用费用。默认不开启该路径；网页规则模式仅提供有限匹配，不等同于 Agent 的自由问答能力。

## 升级、备份与交付

升级前停止旧服务并备份配置、设备身份和数据库。不要在 Node 进程仍运行旧代码时，把页面静态文件的更新当成服务端升级完成。

```bash
pnpm install --frozen-lockfile
pnpm check
pnpm desktop:build
pnpm desktop:check
pnpm package
```

源码打包需要干净的 Git 工作区，以当前提交为准，并生成 SHA-256 校验文件。打包器会拒绝被误跟踪的本机配置、身份或运行数据；仍应审查源码中是否意外写入凭据。

源码包不包含 `.git`、依赖安装目录或私有配置。接收方按 [部署配置](deployment.md) 安装依赖与设置环境，不应复制其他人的设备身份。
